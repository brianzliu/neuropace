## 1. What the product is

A student wears a NeuroSky MindWave Mobile 2 during a lecture. NeuroPace transcribes the
lecture with Deepgram, tracks focus from the EEG, and when the student drifts (or presses
a key) it shows a one-line catch-up. After the lecture it generates study material only
for the moments they missed, then restudies those moments and learns which kind of
explanation works for that student.

Everything runs locally: one Python process (FastAPI + asyncio) serving a built React SPA
on `http://localhost:8765`.

## 4. The one structural change tonight: macOS Bluetooth

**Do not rewrite this. It is the fix that made the headset work on this machine, and it is
tested.** Evidence, from the prior session:

- Opening `/dev/cu.MindWaveMobile` at 57600 baud for 15 s returned `bytes 0 valid_packets 0`.
  The macOS serial path is silent. The pipeline had only ever been validated on Windows/COM3.
- Opening the paired device's RFCOMM channel with IOBluetooth returned
  `first bytes [170, 170, 2, 186, 4, 65, ...]` (0xAA 0xAA ThinkGear sync) and
  `bytes 60076 chunks 3795` in the same 15 s.

`mindwave/macos_rfcomm.swift` is a small helper that opens the RFCOMM channel and writes
untouched ThinkGear bytes to stdout. `mindwave/macos_transport.py` compiles it once with
`xcrun swiftc` (cached by source hash under `~/Library/Caches/NeuroPace/`) and presents a
pyserial-shaped object. `ThinkGearReader` falls back to it when a darwin MindWave serial
port opens but delivers no valid packets for 5 s. Signal processing stays in Python.

## 7. Known behavior worth knowing (not bugs)

- The MindWave stops streaming when it is not being worn (`poor_signal 200`) and the link
  goes idle. The app reports "Headset lost / Reconnecting" and keeps recording the lecture.
  A new session re-attaches it. This is correct, designed behavior.
- One artifact-contaminated second inside an in-progress EEG drop now ends that drop
  (`state: bad`, `exit` event). This follows from `allowed = baseline.ready and valid` in
  `neuropace/signal/features.py`, which deliberately stops a drop from *opening* on stale
  window values. Measured, intentional, covered by
  `tests/test_features.py::test_artifact_cannot_open_a_drop_from_old_window_values`.
- Free-tier model quotas were hit repeatedly tonight (OpenRouter credit, then Gemini's
  daily cap). The client now blocks further calls for 300 s after a quota error and paces
  Gemini to 5 req/min. Current provider (OpenRouter, `openai/gpt-4.1-mini`) has budget:
  $0.050 used of $50 as of 22:45, all of tonight's testing included.
